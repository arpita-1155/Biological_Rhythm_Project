📊 Dataset
The primary classification dataset used in the project is the Depresjon Dataset, containing actigraphy and behavioral monitoring data.
The project uses subject-level information from:
- Condition subjects
- Control subjects
The dataset contains 55 subjects:
- 23 condition subjects
- 32 control subjects
The raw activity recordings are cleaned and resampled to 5-minute intervals before feature extraction.
Raw datasets are not required for running the Streamlit dashboard because the processed results and trained models are already included separately.

🔬 Feature Extraction
1. Cosinor Analysis
A 24-hour Cosinor model is used to characterize broad daily activity rhythms.
Extracted features include:
- Mesor
- Amplitude
- Acrophase
- R²
The model represents activity using a sinusoidal 24-hour component.
2. Wavelet Transform
Continuous Wavelet Transform is used to analyze activity patterns across different time scales.
The project analyzes periods between approximately:
2 hours → 48 hours

Wavelet-derived features include:
- Total wavelet power
- Short-period power
- Intermediate-period power
- Circadian power
- Long-period power
- Power ratios
- Dominant period
- Dominant power
The circadian band used in feature extraction corresponds to approximately:
18 → 30 hours

3. Sample Entropy
Sample Entropy is used to quantify the regularity and complexity of the activity signal.
4. Permutation Entropy
Permutation Entropy measures the complexity of the signal based on ordinal patterns.
5. Detrended Fluctuation Analysis
DFA is used to characterize long-range scaling behavior in the activity signal.
The extracted feature is:
DFA Alpha

🤖 Machine Learning
The extracted features are combined into a subject-level feature table.
Two classification models are used:
Random Forest
A Random Forest classifier is trained using the extracted biological rhythm and complexity features.
XGBoost
An XGBoost classifier is also trained using the same feature representation.
🔒 Subject-Level Validation
A major methodological component of the project is preventing data leakage.
Instead of randomly splitting individual activity segments, the project keeps each subject separated during validation.
The classification pipeline uses:
GroupKFold

with:
Group = Subject ID

Therefore, activity information belonging to the same subject is not placed in both the training and validation groups.
This provides a more realistic subject-level evaluation.

Complexity Analysis

- Sample Entropy

- Random Forest

🚀 Running the Project
1. Clone or download the project
git clone <YOUR-GITHUB-REPOSITORY-URL>
cd Biological_Rhythm_Project

2. Create a virtual environment
Windows
python -m venv .venv

Activate it:
.venv\Scripts\activate

3. Install dependencies
python -m pip install -r requirements.txt

4. Run the Streamlit dashboard
From the project root:
streamlit run app.py

The dashboard will open in your browser.

⚠️ Important Notes
Research / Educational Use
This project is intended for academic, research, and demonstration purposes.
The machine-learning output is not a clinical diagnosis and should not be used as a medical decision-making system.
Model Evaluation
The dashboard models are trained using the complete available feature dataset for demonstration/inference.
Model performance should instead be evaluated using the separate subject-level GroupKFold cross-validation results.
Dataset
Raw datasets may have separate usage and redistribution requirements. Verify the dataset's terms before publishing raw data in a public repository.
